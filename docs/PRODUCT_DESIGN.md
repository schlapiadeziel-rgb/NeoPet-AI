# NeoPet AI 产品与交互设计

## 产品定位

NeoPet AI 是一个跨电脑与移动设备的 AI 角色伴侣。核心不是“聊天框换皮”，而是一个会观察交互状态、用动作表达、可由用户配置模型和角色的长期桌面宠物。

## 参考产品带来的设计取舍

- Desktop Mate：学习角色停靠窗口、追随鼠标、缩到屏幕边缘和不打断工作的设计。
- Shimeji / Desktop Goose：学习随机行为、拖动反馈和“宠物自己有事做”的生命感。
- Open-LLM-VTuber：学习透明桌宠模式、语音打断、表情映射与本地运行能力。
- DesktopFriends：学习电脑与 Android 双端、模型自由配置和多设备连接。
- Live2DPet / Warashi：学习主动对话、长期记忆、屏幕感知和安装向导，但屏幕感知必须明确授权并默认关闭。

不复制第三方角色、美术、声音或受限制代码。电影和动画只能作为风格参考，生成结果必须保持原创或取得授权。

## 平台形态

### Windows / macOS / Linux

- 透明置顶宠物窗口，默认仅显示宠物。
- 默认宠物本体约 190 × 210 px，紧凑窗口约 300 × 360 px，只比小型桌宠略大，不占据主要工作区。
- 单击互动、双击聊天、右键设置、拖动移动。
- 可切换鼠标穿透，长时间闲置缩到屏幕边缘。
- 聊天、模型、记忆和角色管理在展开面板中完成。

### Android

- 应用内完整宠物与聊天。
- 用户主动授权后可启用系统悬浮层。
- 前台服务、常驻通知与电量策略必须清晰可控。

### iOS / iPadOS

- 应用内完整宠物与聊天。
- 使用 WidgetKit、Live Activity 和通知提供系统外陪伴入口。
- 不承诺跨应用自由移动的系统级悬浮宠物。

### 通用移动端

- PWA 提供 Android、iOS、平板和移动浏览器的共同基础版本。
- 原生壳只负责平台能力，角色、动作协议、模型配置和会话结构保持一致。

## 统一动作协议

AI 输出 `reply`、`emotion` 和 `action`：

- `emotion`: neutral / happy / sad / curious / excited
- `action`: idle / listening / thinking / speaking / wave / nod / happy / dance / sleep

静态宠物图片使用整体变换表达动作；Live2D 或精灵表角色将动作映射到原生动画片段。

## 隐私边界

- API 密钥不提交到仓库；桌面端使用系统安全存储，移动网页端仅保存到浏览器会话。
- 屏幕、摄像头、麦克风和悬浮窗权限默认关闭，使用时逐项说明目的。
- 邮箱验证码正式发布时必须由服务端发送，客户端不能内置 SMTP 授权码。
